Before you plot

A quick guide to placing shops and stalls. These checks apply to every hall.

  • Stay on the usable floor. Keep the whole stall inside the hall, clear of walls, outside areas and floor holes. Width and length must be positive multiples of the size step.
  • Leave room for people. Keep {{ passage() }} m clear in front of the full width of every open side. At least one side must stay open; never block another stall’s access.
  • Respect the marked clearances. Keep {{ rules().peripheralClearance }} m from external walls. Keep restricted zones and entry, exit, service and emergency access clear. Hidden restrictions still apply.
  • Shared walls are allowed. Stalls may touch or stand close together on closed sides without overlapping. With Hall corners enabled, keep a full passage width from at least one of the two walls meeting at a corner.
  • Check every change. Add, draw, move, resize, rotate, duplicate and assisted placement are validated. Invalid drops return to their previous position; invalid edits are rejected.
  • Resolve issues before saving. Use the Rules tab to locate problems. Existing invalid layouts stay visible for repair. Save and Update are blocked until placement issues are resolved; the server can also reject a write.
Hall settings, snapping & access

B2B and B2C passages can each be set from 1.5–5 m (never below 1.5 m); a missing setting defaults to 3 m. With emergency access enabled, exits keep at least 3 m clear, even with narrower aisles. Changing settings rechecks the layout without rearranging stalls. Invalid saved passage values must be corrected.

All sizes and positions are in metres. X/Z describe the stall centre; openings rotate with the stall. Move snapping aligns edges, so half-metre centres can be valid. Turning snap off does not disable size or clearance checks. Draw stays grid-based; Add rounds sizes to the configured step.

Circular and irregular outlines, holes and separate floor regions matter. A stall cannot bridge outside space. Exterior space does not count as usable passage in front of an open side.

Passage, no-construction, emergency/entry access, facility, restricted foyer, partition and smoke-curtain zones prohibit stalls. Facility, partition and smoke-curtain buffers default to 1 m; hall or individual-zone settings can override them. Door access uses its configured depth, otherwise the event passage width. Walkable passage zones can serve an open side; physical restrictions cannot.

Stall status, numbering & splitting

New stalls are AVAILABLE. AVAILABLE and BOOKED stalls occupy space; CANCELLED stalls do not. Removing a saved stall cancels it and keeps its number; an unsaved stall is removed. Save or Update to keep these changes. New and duplicate stalls receive permanent numbers from the server.

Split only AVAILABLE stalls into 2–100 equal children along local X or Z. Passage gaps come from the parent’s area, and child sizes must fit the grid. A back-to-back split has exactly two children and must pass the same opening checks.

Preview numbers such as parent-A and parent-B are provisional. Confirm requires a saved parent and layout matching the saved geometry/settings; Update first if needed. Children appear only after server confirmation. An unavailable split keeps the parent; an editor change during a request requires a fresh review or reload.

AI proposals, imports & offline work

AI proposals must pass the same rules. Review, then Apply; placements are checked again. Changed fitting counts need another review, hall changes expire pending proposals, and removal proposals expire if the stalls changed. Applying a proposal does not save the layout.

Excel imports drop stalls outside the basic hall boundary but retain overlaps for repair. Audit before saving. SelfCare imports preserve source geometry and recognized restrictions, including hidden ones; a visual label or generic coloured area alone is not a configured access restriction.

Offline sample and custom halls still enforce placement rules. Saving, server audit and AI generation need the backend. Save before leaving: unsaved page work is not permanent. Saving a master hall plan requires an existing server hall; local halls can be saved in a layout.

Suggestions, capacity & check limits

Locate highlights a problem. A rejected placement may offer a nearby valid spot for the same size and orientation. Duplicate searches for a fresh location. Hiding clearance guides never disables validation.

Free-space “fit” counts show alternative grid positions, not simultaneous capacity. Occupancy uses active stall area divided by nominal hall area; it does not deduct passages or restrictions. Shop totals include cancelled records.

These checks cover floor placement and configured access geometry. They do not validate ceiling height, structural loads or complete evacuation routes. BOOKED status alone does not lock editing. The saved layout can be checked separately on the server.
